# P7 — Handwritten Sudoku Reader and Solver (Search + CSP + NN)

A Sudoku is drawn as a 9×9 mosaic of real MNIST digit images. A CNN reads every cell and gives a
probability for each digit 1–9. When it misreads a digit the puzzle becomes contradictory; AC-3
detects the conflict, a search (UCS / Greedy / A*) looks for the cheapest set of cell corrections
(cost = how much less likely the new digit is), and the CSP solver tests each corrected puzzle.
The first corrected puzzle with exactly one solution wins. If none exists within 3 corrections the
system answers **"No solution: puzzle unreadable"** and lists the 5 least confident cells.

```
mosaic ──► blank rule + CNN ──► read grid + probabilities ──► AC-3 check ──┬─ consistent & unique ─► solved
 (252×252)   (sudoku/nn)                                      (sudoku/csp)  │
                                                                            └─ conflict ─► correction search
                                                                                           (sudoku/search)
                                                       goal test = CSP (AC-3 + FC + MAC) ◄──┘   │
                                                                                                ▼
                                                                 corrected + solved   or   "unreadable"
```

## Setup

Requires **Python 3.12** (pins tested on 3.12.3, Linux, CPU only). Recent numpy/pandas pins may not
install on older Python versions.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

`requirements.txt` pins every package version that was installed and tested. It contains
`--extra-index-url https://download.pytorch.org/whl/cpu`, so pip finds the CPU-only
`torch==…+cpu` / `torchvision==…+cpu` wheels (avoids the multi-GB CUDA build) while all other
packages still come from PyPI in the same command. `--index-url` is deliberately not used: it would
replace PyPI and break the other installs.

## Run order

Run these from the repository root with the venv active. Times are from a 12-core laptop CPU.

```bash
python make_data.py        # download MNIST, split, generate the puzzle bank         (~10 s + download)
python train.py            # CNN + logistic regression, calibration, digit pools    (~1 min)
pytest                     # 98 tests                                                (~20 s)
python run_demo.py         # integrated demo: --seed 7 --misreads 2 by default       (~5 s)
python run_experiments.py  # Experiments 1-3 + 100-puzzle recovery study            (~3.5 min)
```

| Script | Options | Writes |
|---|---|---|
| `make_data.py` | `--seed N`, `--quick` (6 puzzles per given count into `puzzles_quick.npz`) | `data/raw/`, `data/processed/`, `results/data/sample_mosaic.png` |
| `train.py` | `--seed N` (training only; the split seed comes from `make_data.py`), `--quick` (1 epoch, 5k images → `models/quick/`) | `models/`, `data/processed/digit_pools.npz`, `results/nn/` |
| `run_demo.py` | `--seed N`, `--misreads 0..4`, `--givens 25/30/35`, `--algorithm ucs/greedy/astar` | console trace, `results/demo/*.png` |
| `run_experiments.py` | `--quick` (2 seeds × 3 puzzles, ~25 s → `results/experiments/quick/`), `--replot` (recompute summaries and plots from the per-puzzle CSVs) | `results/experiments/*.csv`, `*.png` |

MNIST is downloaded with `torchvision.datasets.MNIST` (the yann.lecun.com page is often
unreachable) and kept in `data/raw/`. Data, puzzle banks and model weights are git-ignored and
fully regenerated by the commands above; everything in `results/` is committed except the
`quick/` smoke-test folders.

All seeds, thresholds and limits are in **`sudoku/config.py`** (default seed `SEED = 7`).

## What the demo shows

`python run_demo.py --seed 7 --misreads 2` prints, in order: the generated puzzle, the CNN reading
with per-cell confidence (misread cells marked `*`), the AC-3 contradiction and the duplicate
digits, the search trace (every popped state with g, h and f), the UCS / Greedy / A* node counts,
the correction log (cell, read digit, new digit, cost), the solved grid with an exact-recovery
check, CSP work with BT / BT+FC / BT+FC+AC-3 / MAC, and recovery with NN-guided correction on vs off.
Figures: `demo_pipeline.png` (mosaic → reading → solution), `demo_search.png`, `demo_csp.png`,
`demo_nn_on_off.png`. `--misreads 4` shows the "unreadable" path.

## Tests

`pytest` runs 98 tests in about 20 s. The tests that need the trained model are skipped (not
failed) if `train.py` has not been run. The brief's categories are pytest markers:

```bash
pytest -m normal       # 32 normal cases, e.g. CSP gives identical solutions in all modes, UCS on a
                       #   hand-made example with known cost and node counts, reader output sums to 1,
                       #   generator makes unique puzzles, pipeline recovers a 1-misread mosaic
pytest -m edge         # 11 edge cases, e.g. already-solved grid, 0 misreads (no search), 17-given
                       #   puzzle, correction needed at exactly the 3-correction budget
pytest -m impossible   # 12 impossible cases, e.g. two confident equal givens -> "No solution:
                       #   puzzle unreadable" + least confident cells; contradictory givens -> AC-3 failure
```

Other tests check the A* heuristic is admissible and consistent by brute force over every state of
a small problem, and that UCS and A* return the brute-force optimum.

## Results (seed 7)

| | |
|---|---|
| CNN (MNIST test, digits 1–9) | accuracy 98.49 %, ECE 0.0055 → 0.0039 after temperature scaling (T = 0.868) |
| Logistic regression baseline | accuracy 92.24 %, ECE 0.0051 → 0.0133 after temperature scaling |
| Exact recovery, 100 puzzles per level | 0 misreads 100 %, 1: 95 %, 2: 89 %, 3: 87 %, 4: 0 % (budget is 3 corrections) |
| NN off / random correction | 0 % / 28 % exact recovery at 1 misread, 0 % at 2–4 |

Details, the other experiments and their caveats: `results/experiments/FINDINGS.md`;
NN metrics: `results/nn/metrics.csv`, `confusion_*.png`, `reliability.png`.

## Extensions implemented

Uniqueness goal (`count_solutions(limit=2)`), A* with an admissible and consistent heuristic,
temperature scaling, MAC (AC-3 during search), MRV ordering option, a second random baseline
restricted to the search's candidate cells, and a no-temperature arm in Experiment 3.
